# 墨读·小说引力场 — 前后端双端需求文档

> 本文档由《接口需求文档》优化而来，从"纯前端 SPA 契约"升级为**「前端（React SPA）+ 后端（go-admin）双端契约」**。
>
> - **当前状态**：前端已完成纯前端实现（localStorage 持久化，无 HTTP API）。
> - **演进目标**：接入本仓库的 go-admin 后端，前端改为调用 REST API，数据持久化从 localStorage 迁移到数据库。
> - **后端方案**：按 go-admin 业务开发规范（见 `docs/LLM使用说明.md` §7）落地为 `app/app/novel/` 新业务模块，表前缀 `app_novel_*`。

---

## 1. 总览

| 项目 | 说明 |
|---|---|
| 前端 | 纯前端 SPA：Vite 6 + React 19 + TypeScript 5.8，CSR，无路由库，状态集中在 `App.tsx` |
| 后端 | go-admin（Gin + GORM + Casbin + JWT）。**双前缀分离**：管理后台（`app/admin/`）走 `/admin-api/v1`，小说推荐平台走独立 `/web-api/v1`，两套前缀互不干扰（见 §4.1） |
| 后端归属 | **`app/app/novel/`（个性化业务层）**，与 `app/` 下现有 `user` 子业务同级 |
| 表前缀 | `app_novel_*`（表，如 `app_novel_book`） |
| 数据源演进 | 前端 mock → localStorage（现状）→ MySQL/PostgreSQL（后端接入后） |
| 读者账号 | 复用 `app/app/user` 的 `app_user` 表（手机号/邮箱登录，AES 加密），平台扩展资料放 `app_novel_reader_profile` |
| 内容管理 | 后台「管理员/编辑」角色通过本模块接口管理书籍；读者发帖/发书评/收藏 |

### 2.3 前端业务操作（App.tsx 事件契约 → 后端接口映射见 §4.2）

| 前端操作 handler | 说明 | 后端落库规则 |
|---|---|---|
| `handleLikePost` / `handleDislikePost` | 赞/踩互斥，`likes±1` 下限 0 | 互动记录表 + 计数冗余，事务内互斥 |
| `handleCollectPost` | 收藏 `collections±1` | `app_novel_post_collect` 增/删 |
| `handleAddPostComment` | 评论/回复，`@昵称` 前缀 | `app_novel_post_comment` 插入（携带 `reply_to_user`） |
| `handlePublishPost` / `handleDeletePost` | 发帖（校验 5000~10000 字）/ 删帖 | 校验内容长度，删帖级联清理互动 |
| `handleToggleBookshelf` | 书架增/删 | `app_novel_bookshelf` upsert/delete |
| `handleAddReview` | 书评 + 评分联动（见 §5 规则①） | 书评表插入 + 书籍评分/`review_count` 事务更新 |
| `handleDeleteUserReview` | 删"我的书评"（不回溯书籍聚合） | 删除书评记录（含软删/审计可配） |
| `handleSaveBook` | 新增/编辑作品 | `POST/PUT` 由 admin/编辑权限执行 |
| `handleSelectBookByTitle` | 帖子关联小说跳转 | 后端按 `title` 精确匹配 |
| `onLoginSuccess` | 仅写名字（无真实鉴权） | 后端走 `app_user` 真实登录 + JWT |

### 2.4 公共业务规则（前后端双端一致，后端为最终保障）

1. **书籍筛选**：分类精确 + 连载状态精确 + 字数区间（`word_count_wan` 落入 4 档）+ 关键字（书名/作者/tags 不区分大小写）。
2. **排序**：高分优先 = `rating desc`；热门热度 = `clicks desc`；最新发布 = `publish_date desc`。
3. **评分联动**：新书评使 `rating = (旧rating×reviewCount + 新评分)/(reviewCount+1)`，保留 1 位小数；`review_count + 1`。
4. **赞踩互斥**：同一用户对同一帖只能居其一（赞→点踩须先撤销赞，反之同理），两侧计数均下限 0。
5. **帖子字数**：正文 5000~10000 字，`summary = 前 150 字`，`read_time = ceil(字符数/400)` 分钟。
6. **删除语义**：书籍删除须级联清理书架/书评（或软删策略）；帖子删除清理互动与评论。

## 3. 数据模型契约（字段蓝本，来自 src/types.ts）

> 前端类型定义与后端表**字段一一对应**，下列字段名/含义双端通用，后端负责持久化与校验。

- `Category`：`'玄幻仙侠' | '都市职场' | '悬疑推理' | '科幻末世' | '古代言情' | '轻小说'`（筛选时多一个 `'全部'`）。
- `SortOption`：`'最新发布' | '高分优先' | '热门热度'`。
- `BookStatus`：`'连载中' | '已完结'`。
- 关联：`Book.reviews: Review[]`、`Post.comments: PostComment[]`、`Post.tags`（单一话题标签）。

**Book**（必填项：`id/title/author/cover/rating/reviewCount/status/category/tags/slogan/description/clicks/publishDate/wordCount/chapters/reviews`；可选：`isFeatured/url`）。

**Review/Rating**：`id, userName, avatar, rating(1~5), content, date, likes, bookId/bookTitle/bookCover(关联快照)`。

**PostComment**（字段见 `src/types.ts`）：`id`、`userName/avatar/content/date`、`likes/isLiked`、`replyToUser`、`replyToCommentId`（预留）。

**Post**：`id, title, userName, avatar, content(5000~10000字), summary, date, wordCount, readTime, likes/isLiked, dislikes/isDisliked, collections/isCollected, comments[], tags(单项)、bookTitle/bookId(可选关联)`。

**UserProfile**：`name, avatar, bio, email, joinDate, preferredCategories[]`（后端替换 `joinDate` 为 `created_at`，`name` 复用 `app_user.nickname`，另存 2 个通知开关）。

## 4. 后端开发方案（go-admin）

### 4.1 归属与代码结构

**接口功能放在 `app/app/` 目录下（个性化业务层），新建子业务 `novel`**，理由：`app/admin/sys/` 为系统基础服务（RBAC/日志/监控），`app/plugins/` 为插件（CMS/文件/消息），小说推荐属于平台主体业务，与现有 `app/app/user/`（业务用户）同级。放置其他位置会破坏「平台业务 / 系统 / 插件」的划分。

```
app/app/novel/                 ★ 新增模块（表前缀 app_novel_*）
├── models/                    #   GORM 模型（TableName() 方法、敏感字段加密、CreatedAt 等公共列）
│   ├── novel_book.go
│   ├── novel_book_review.go
│   ├── novel_post.go
│   ├── novel_post_comment.go
│   ├── novel_post_like.go         # 赞/踩记录（type 区分）
│   ├── novel_post_collect.go      # 收藏记录
│   ├── novel_bookshelf.go         # 书架
│   └── novel_reader_profile.go    # 读者扩展资料
├── service/<表名>.go           # GetPage/Get/Insert/Update/Delete（含联动/事务，见 §4.4）
├── service/dto/<表名>.go       # 请求体（QueryReq 内嵌 dto.Pagination，字段带 search:"..." 标签）
├── apis/<表名>.go              # 薄 handler（MakeContext/MakeOrm/Bind/MakeService）
└── router/<表名>.go            # init() 中往 routerNoCheckRole / routerCheckRole append
```

**路由注册三步（唯一必须的手动改动）**：
1. `app/app/novel/router/router.go`（仿照 `app/app/user/router/router.go`）：包级声明 `routerNoCheckRole` / `routerCheckRole` 两个切片 + `InitRouter()`。
2. `app/app/novel/router/` 下每个模块文件在 `init()` 里 append 注册函数。
3. `app/app/init.go` 的 `AllRouter()` 中 append `novelRouter.InitRouter`（根 `app/init.go` 已自动汇总 `appRouter.AllRouter()`，**无需改动**）。

**★ 双前缀隔离（本模块关键差异，勿沿用 admin 路由写法）**：
- 管理后台（`app/admin/**`）路由分组用 `global.RouteRootPath + "/v1"`（即 `/admin-api/v1`），**与小说平台无关**；
- 小说平台**必须自建前缀常量**，不可使用 `global.RouteRootPath`（否则会串到 `/admin-api/v1` 下），在 `router/router.go` 中定义：

```go
// 小说平台独立前缀（与管理后台 /admin-api 分离，互不干扰）
const NovelRouteRootPath = "/web-api"

// InitRouter 内使用：
// v1 := r.Group(NovelRouteRootPath + "/v1")
```

- Casbin 权限按「请求路径 + 方法」入库，`/web-api/v1/app/novel/*` 与 `/admin-api/v1/**` 天然分区，策略互不影响；
- swagger 注解 `@BasePath` 为管理后台 `/admin-api/v1`，小说平台接口如需文档化，另开独立注解组或在 `docs/` 增加第二份 spec（待办，见 §8）。

**必须执行 `go generate`**：每次新增接口后/打包前运行，否则后台「接口数据同步」不会录入新接口。

### 4.2 接口清单（对照前端操作，全部 `/web-api/v1` 前缀）

> 鉴权约定：`/app/novel/*` 全部挂 `middleware.Auth()`；需角色/按钮权限的挂 `middleware.AuthCheckRole()`（admin 全通过）。按钮权限命名 `novel:<表>:<作用>`。

#### 书籍（对前台只读，内容管理需 admin/编辑）

| 方法/路径（前缀 /web-api/v1） | 权限 | 前端对应 |
|---|---|---|
| `GET /app/novel/book` | 登录 | 书库/首页筛选排序列表（分页） |
| `GET /app/novel/book/:id` | 登录 | 书籍详情（含 reviews） |
| `POST /app/novel/book` | `novel:book:add` | 新建/编辑（BookFormModal） |
| `PUT /app/novel/book/:id` | `novel:book:edit` | 编辑 |
| `DELETE /app/novel/book/` | `novel:book:del` | 删除（body `{"ids":[...]}`） |
| `GET /app/novel/book/rank?type=rating|click` | 登录 | 榜单页（可复用列表+sort） |
| `GET /app/novel/home` | 无需登录 | 首页聚合：精选轮播 + 热门 TOP5 + 最新/热门帖子 |

#### 书评

| 方法 | 权限 | 前端对应 |
|---|---|---|
| `POST /app/novel/book-review` | 登录 | `handleAddReview`（含评分联动事务） |
| `GET /app/novel/book-review/page?bookId=&filter=all\|five\|hot` | 登录 | 书评圈筛选 |
| `DELETE /app/novel/book-review/` | 本人 | `handleDeleteUserReview` |

#### 长文帖子与互动

| 方法 | 权限 | 前端对应 |
|---|---|---|
| `GET /app/novel/post/page?sort=latest|hot&topicTag=` | 登录 | 首页/用户中心帖子列表 |
| `GET /app/novel/post/:id` | 登录 | 帖子详情（含评论与我的互动状态） |
| `POST /app/novel/post` | 登录 | `handlePublishPost`（内容 5000~10000 字校验） |
| `DELETE /app/novel/post/` | 本人 | `handleDeletePost` |
| `POST /app/novel/post/:id/interact` | 登录 | 点赞/踩/收藏，body `{type: like|dislike|collect,  action: add|cancel}`（赞踩互斥 §2.4-4） |
| `POST /app/novel/post/:id/comment` | 登录 | `handleAddPostComment`（含 `replyToUser`） |
| `DELETE /app/novel/post-comment/:id` | 本人 | 删除评论（可选） |

#### 书架与读者资料

| 方法 | 权限 | 前端对应 |
|---|---|---|
| `GET /app/novel/bookshelf` | 本人 | 我的书架 |
| `POST /app/novel/bookshelf` | 本人 | `handleToggleBookshelf` 增 |
| `DELETE /app/novel/bookshelf/:id` | 本人 | 移除 |
| `GET /app/novel/reader-profile` | 本人 | 用户中心 |我的设置` |
| `PUT /app/novel/reader-profile` | 本人 | 头像/昵称/简介/邮箱/偏好分类/通知开关更新 |

> **管理端复用**：书籍/书评/帖子/读者均派生 parent from 后台「系统管理 → 代码生成」五层模板（模型/服务/DTO/API/路由），逐表生成后按 §4.4 补充联动逻辑。

### 4.3 数据表设计（DDL，MySQL 为主体示例）

> 项目需同时维护 `app_mysql.sql` / `app_pgsql.sql` 两套脚本（PG 仅列类型差异：`bigint`→`bigserial`、`varchar/n` 同宽、`datetime`→`timestamp`）。索引列已在建表内声明。

```sql
-- app_novel_book 书库（≈ modu_books，含书评聚合列）
CREATE TABLE `app_novel_book` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  `title`           VARCHAR(100)     NOT NULL COMMENT '书名',
  `author`          VARCHAR(64)      NOT NULL COMMENT '作者',
  `cover`           VARCHAR(500)     NOT NULL DEFAULT '' COMMENT '封面 URL 或 base64',
  `rating`          DECIMAL(3,1)     NOT NULL DEFAULT 5.0 COMMENT '综合评分，1 位小数',
  `review_count`    INT UNSIGNED     NOT NULL DEFAULT 0  COMMENT '书评数',
  `serial_status`   CHAR(1)          NOT NULL DEFAULT '1' COMMENT '连载状态:1-连载中 2-已完结',
  `category`        CHAR(2)          NOT NULL COMMENT '分类字典 app_novel_category',
  `tags`            JSON             NULL COMMENT '标签数组（ban，#开头）',
  `slogan`          VARCHAR(30)      NOT NULL DEFAULT '' COMMENT '一句话推荐语',
  `description`     VARCHAR(500)     NOT NULL DEFAULT '' COMMENT '简介',
  `clicks`          INT UNSIGNED     NOT NULL DEFAULT 0  COMMENT '点击数',
  `publish_date`    DATE             NULL COMMENT '发布日期 YYYY-MM-DD',
  `word_count`      INT UNSIGNED     NOT NULL DEFAULT 0  COMMENT '字数（整数，用于筛选）',
  `chapters`        INT UNSIGNED     NOT NULL DEFAULT 0  COMMENT '章节数',
  `is_featured`     TINYINT          NOT NULL DEFAULT 0  COMMENT '首页精选 0 | 1',
  `read_url`        VARCHAR(500)     NOT NULL DEFAULT '' COMMENT '阅读链接',
  `status`          CHAR(1)          NOT NULL DEFAULT '1' COMMENT '上架:1-上架 2-下架',
  `create_by`       BIGINT           NOT NULL COMMENT '创建者(admin_sys_user.id)',
  `update_by`       BIGINT           NULL COMMENT '更新者',
  `created_at`      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_book_category` (`category`),
  KEY `idx_book_serial` (`serial_status`),
  KEY `idx_book_featured` (`is_featured`),
  KEY `idx_book_clicks` (`clicks` DESC),
  KEY `idx_book_rating` (`rating` DESC),
  KEY `idx_book_publish` (`publish_date DESC`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='书库';
```


**字典（`admin_sys_dict`）**：`app_novel_category`（7 个分类，不含'全部'）、`app_novel_serial_status`（连载中/已完结）、`app_novel_topic`（7 个话题标签）、`app_novel_book_status`（上架/下架）。字典接口属于管理后台模块，前缀仍为 `GET /admin-api/v1/admin/sys/dict`（已在 CasbinExclude 白名单，前台可直调）。

**索引策略**（与 H16 教训一致，核心查询路径必须建索引）：分类/连载状态/精选/排序（clicks、rating、publish_date）、`book_review(book_id)`、`post_comment(post_id)`、书架与互动表均加 `唯一索引` 兜底并发（借鉴 M16 修复）。

### 4.4 业务规则落库（service 层关键实现）

| 规则 | 实现 |
|---|---|
| 评分联动（§2.4-3） | `InsertReview` 用 **GORM 事务**：插入书评 → 锁定书籍行 → `rating = `(旧rating×旧数 + 新评分)/(新数)` 保留 1 位小数 → `review_count+1` → 提交。事务内使用 `tx.Create`（同 user 模块 L24 的 tx 用法） |
| 帖子互动（§2.4-4） | `interact` 接口同事务：先查 `app_novel_post_like` 是否存在 `(user_id,post_id)`；存在→删记录并 `likes/dislikes -1`（下限 0）；不存在→插入并 `+1`。**同一用户同一帖子唯一记录（UNIQUE 兜底）**，实现赞/踩互斥 |
| 收藏 | `app_novel_post_collect` upsert / 删除，同时 `collections ±1` |
| 书本删除 | 事务级联：书籍→其 `reviews/bookshelf` 清理（帖子 `ref_book_id` 置 NULL）；帖子删除→清理 `like/collect/comment`（软删 `status=2` 可选，配合审计） |
| 帖子新增 | 校验 `content` 5000~10000 字；`summary=`前 150 字 + `...`；`read_time=ceil(字符/400)`；`ref_book_id` 存在性检查 |
| 销量/点击 | `clicks` 由查看详情接口 `+1`（防刷新刷量可选：按 IP/用户会话当日去重） |

**高并发取舍**：排序/分页直接 `ORDER BY` 冗余计数列（`likes/clicks`），配合索引；互动计数以权限行 + 唯一约束兜底，不依赖同查后再写的非原子读改写（`M16` 修复走 network）。

### 4.5 DTO / 响应 / 权限 / 接口同步约定

- **DTO**：每个模块 `QueryReq` 内嵌 `dto.Pagination`，字段带 `search:"type:...;column:...;table:..."` 标签；`GetPage/Get/Insert/Update/Delete/Export` 子类化。多列搜索（书名/作者/tags）在 service 层用 `MakeCondition` + `自拼接 OR`，不依赖默认 `contains`。
- **响应**：统一返回 `core/dto/response` 的 `OK/Error/PageOK`；业务错误用 `CustomError#code#msg`。
- **错误码与文案**：新增消息码在 `config/base/lang/app_novel.go` 注册（如「书籍不存在」「帖子字数需在 5000~10000 之间」）。
- **权限**：内容管理（增/删/改、删除书）用 `novel:book:add/edit/del`系 AdminOnly（对应"编辑角色"）；读者操作只需登录（`Auth`）并在 service 用 `CurrUserId` 限界。
- **接口同步**：每次改动后运行 `go generate`，在后台「系统管理→接口管理→同步」录入；方法注释必须 `// 方法名 功能说明` 格式。

## 5. 前端接入后端改造点（对接顺序）

1. **请求层**：新增 `src/api/` 封装（`fetch`/axios → `/web-api/v1`，统一 `Authorization: Bearer`、错误 toast）。后端 `corsOrigins` 需加入前端域名；开发期可配置 `trustedProxies`（见 `docs/LLM使用说明.md` §12-7）。
2. **鉴权**：把 `onLoginSuccess` 改为真实登录（复用 `app/app/user` 的 login/JWT），`currentUser`/`userProfile` 由接口返回而非内存写。
3. **数据源切换**：`useState(lazyInit localStorage)` 改为 加载态 + 分页接口；书库/书评/帖子/书架/资料 5 处读写替换为接口调用，localStorage 仅留作离线兜底。
4. **聚合与联动**：首页轮播 + 榜单 + 书评圈筛选由 `/app/novel/home`、`/book-review/page` 代替本地计算；点赞/收藏态请在详情接口返回 `isLiked/isCollected`（后端由读者当前 `user_id` 推导）。
5. **时间处理**：后端返回时间戳，前端做相对时间（原 `'刚刚'` 语义改为服务端 `created_at`）。

1. 建表：把 §4.3 DDL 导入 `app_mysql.sql` / `app_pgsql.sql`，同时录入字典（`app_novel_*` 四个）。
